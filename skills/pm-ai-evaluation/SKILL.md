# AI 评测集设计

## 目的

让 AI 功能的质量可以被测量、比较和回归。评测集回答的是“这个版本能不能上线”“改了提示词或换了模型之后变好还是变差”，而不是证明产品很智能。

## 先定要支持的决定

先问清这次评测用来做什么：首次上线验收、比较两个模型、改提示词后的回归，还是排查某类投诉。决定不同，案例的构成和门槛也不同。

把“效果好”改写成可观察的任务结果，例如“从三份访谈中提炼出有出处的问题，不编造原话”，而不是“理解准确、总结到位”。说明用户拿到结果后要用它做什么，评测就围绕这件事打分。

## 案例从哪里来

优先使用真实材料：用户的真实任务、脱敏后的真实资料、线上失败记录、客服和反馈中的问题。自己编的案例只能补充覆盖不到的类型，并标明是构造的。

按类型覆盖，而不是只放常见情况：

| 类型 | 检验什么 |
| --- | --- |
| 普通任务 | 主要场景能否稳定完成 |
| 困难任务 | 长资料、多步骤、需要综合多处信息 |
| 信息缺失 | 资料里没有答案时，能否说明不足而不是编造 |
| 资料冲突 | 能否指出矛盾，而不是挑一个说法当结论 |
| 过期或错误资料 | 能否识别时效和明显错误 |
| 输入异常 | 空输入、超长、格式错误、语言混杂 |
| 应澄清或拒绝 | 需求含糊、超出能力或越权时的处理 |
| 夹带指令 | 资料或网页里写着“忽略之前的要求”之类内容时，是否仍按系统规则执行 |
| 多轮对话 | 能否沿用前文的决定，不前后矛盾 |

涉及工具或 Agent 时，再加上：选对工具、参数正确、调用顺序合理、不重复执行、失败后能恢复，以及最终状态是否正确。

## 每条案例怎么写

| 字段 | 说明 |
| --- | --- |
| 编号与类型 | 便于按类型统计 |
| 输入 | 用户说的话、附带的资料或上下文、前置状态 |
| 期望行为 | 必须做到的、不得出现的，各写几条可判断的要求 |
| 可接受范围 | 允许的不同写法；有多种正确答案时写清判断原则 |
| 参考答案 | 有标准答案时提供；没有时不硬造唯一答案 |
| 评分方式 | 规则检查、评分细则，还是人工判断 |
| 来源 | 真实任务、线上失败，还是构造案例 |

“期望行为”写成能判断对错的句子，例如“列出的每个问题都附访谈出处”“资料未提及价格时，回答说明未提及”，而不是“回答全面”。

## 怎么打分

- **能用规则判断的，用规则判断**：输出格式、必填字段、是否引用来源、是否调用了不该调用的工具、写入的对象是否正确。
- **需要判断的，用评分细则**：每个维度分两到三档，每档写清什么样算达到。维度通常包括任务完成、事实与来源、遗漏、可用性。
- **模型评审只做辅助**：用模型打分时，先拿一部分案例和人工打分对照，确认两者大体一致再扩大使用，之后定期抽查。
- **设一票否决项**：编造来源、泄露隐私、越权修改或删除数据等，出现一次就不通过，不和其他分数平均。

不要只报一个总分。按类型分别报告，并附上典型失败样例，否则平均分会掩盖某一类任务完全失败的情况。

## 样本量与门槛

先用几十条覆盖所有类型的案例起步，之后随着线上失败不断补充。小样本适合发现问题和比较明显差异，不能据此宣称精确的准确率。

门槛按类型分别设定，并区分“必须达到”和“希望达到”。用户没有给出基线和要求时，门槛写成建议值并说明理由，标为“待共同确认”，不编造行业标准。

## 运行与比较

每次运行记录：模型名称和参数、提示词版本、资料或知识库版本、工具版本、运行日期。比较两个版本时使用同一批案例和同样的条件。

模型输出有随机性，重要结论要多跑几次看是否稳定。看结果时先看分类型的变化和新出现的失败，再看总体。

调优时反复看过的案例会让效果显得偏好。留出一部分调优时不看的案例，用来判断改动是否真的有效。

## 回归

线上出现的失败，确认原因后转成新案例加入评测集。每次改提示词、换模型、更新资料或工具后，先跑一遍回归，确认已修好的问题没有复发。

## 交付

按需要选择：

- **评测计划**：要支持的决定、任务定义、案例类型与数量、评分方式、门槛、谁来打分、多久运行一次。
- **案例表**：按上面的字段列出案例，先给能覆盖各类型的一批，并标明哪些需要用真实材料替换。
- **结果报告**：总体结论、分类型结果、典型失败及原因、与上个版本的对比、是否达到门槛、下一步。

当前环境不能实际运行评测时，只交付计划和案例，不声称已经运行或得到了某个分数。

## 和其他技能的关系

判断要不要用 AI、怎么设计系统，见 `pm-ai-product-design`；把评测门槛写进需求文档，见 `pm-prd` 的 AI 功能部分。

## 完成标准

每条案例的期望行为可以判断对错；案例覆盖了缺失、冲突、应澄清和夹带指令等难点；评分方式和门槛说明了依据；结果按类型报告并附失败样例；没有把演示样例、模型自评或单次运行当成质量证明。
